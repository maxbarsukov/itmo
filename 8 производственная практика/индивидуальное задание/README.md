# Производственная, технологическая (проектно-технологическая) практика

## Пример утверждённого индивидуального задания

**Тема:** Разработка механизма автоматической анонимизации персональных и секретных данных в журналах сетевого взаимодействия на основе метаданных типов

| № этапа | Название этапа | Период | Задание |
|---------|----------------|---------------|---------|
| 1 | **Инструктаж обучающегося** | 1 | Инструктаж обучающегося по ознакомлению с требованиями охраны труда, техники безопасности, пожарной безопасности, а также правилами внутреннего трудового распорядка. |
| 2 | **Формирование индивидуального задания** | с 16.02.2026 по 01.03.2026 | Ознакомиться с постановкой задачи от руководителя практики. Сформулировать и согласовать функциональные и нефункциональные требования к механизму автоматической анонимизации. Заполнить и утвердить индивидуальное задание в личном кабинете практики. Критерии приёмки: составлен и согласован документ, содержащий списки функциональных и нефункциональных требований. Результат для отчёта: согласованный список функциональных и нефункциональных требований. |
| 3 | **Проектирование архитектуры и требований к системе** | с 02.03.2026 по 09.03.2026 | На основе утверждённого задания разработать детальные требования: поддерживаемые типы данных (простые поля, вложенные объекты, коллекции, ассоциативные массивы, обёртки), поведение при рекурсивных ссылках, производительность, безопасность. Разработать архитектурную схему компонента и определить точки интеграции в систему логирования. Критерии приёмки: схема согласована с руководителем, все типы покрыты. Результат для отчёта: документ с архитектурной схемой. |
| 4 | **Реализация анализатора типовой структуры** | с 10.03.2026 по 17.03.2026 | Разработать компонент, выполняющий рекурсивный анализ типовой структуры передаваемых объектов на основе метаданных классов. Обеспечить обработку вложенных объектов, коллекций, ассоциативных-массивов и обёрток с параметризованными типами. Реализовать кэширование метаданных. Критерии приёмки: все предусмотренные сценарии использования анализатора покрыты автоматизированными тестами; подтверждена стабильная работа на граничных и ошибочных входных данных; механизм интегрируется в систему без деградации её производительности. Результат для отчёта: исходный код модуля и отчёт о покрытии тестами. |
| 5 | **Реализация базового механизма маскирования JSON-структур** | с 18.03.2026 по 22.03.2026 | Разработать компонент для рекурсивного обхода JSON-дерева и замены значений чувствительных полей на маскирующее значение. Обеспечить корректную обработку простых объектов, вложенных объектов и коллекций. Реализовать интеграцию с анализатором типовой структуры. Критерии приёмки: все чувствительные поля в базовых структурах заменяются на ****, ложных срабатываний нет. Результат для отчёта: листинги методов и примеры работы на тестовых данных. |
| 6 | **Реализация поддержки сложных вложенных структур и обёрток** | с 23.03.2026 по 28.03.2026 | Расширить механизм маскирования для поддержки сложных сценариев: ассоциативные массивы внутри списков, generic-обёртки, nullable-значения и рекурсивные ссылки на любом уровне вложенности полей и типов. Обеспечить устойчивость механизма к циклическим зависимостям (без зацикливания и переполнения стека) и к ошибкам десериализации (некорректный JSON, несоответствие типов). Критерии приёмки: механизм корректно заменяет чувствительные поля на маскирующее значение во всех указанных сценариях, включая глубоко вложенные структуры; при обнаружении циклической ссылки механизм прекращает рекурсивный обход и продолжает работу без исключений; при ошибке парсинга или несоответствии типов механизм скрывает тело запроса и записывает предупреждение. Результат для отчёта: исходный код расширенного модуля маскирования, набор интеграционных тестов, демонстрирующих работу на сложных структурах, скриншоты прохождения тестов. |
| 7 | **Тестирование механизма анонимизации** | с 29.03.2026 по 04.04.2026 | Провести многоуровневое тестирование разработанного механизма: 1) Юнит-тестирование — проверка корректности работы модулей на изолированных сценариях (простые объекты, вложенные структуры, коллекции). 2) Интеграционное тестирование — проверка взаимодействия анализатора и маскировщика на сложных типах (например, List<Map<CloudOptional<Int?>?, ProfileRequest?>?>). 3) Сквозное тестирование на тестовом сервисе — генерация моделей и клиентов по OpenAPI-спецификации для сервиса с чувствительными данными, отправка запросов и проверка маскировки чувствительных полей. 4) Проверка производительности — оценка влияния механизма анонимизации на время обработки запросов и потребление ресурсов при различных объёмах данных (от простых сообщений до сложных структур объёмом до 10 МБ); подтверждение отсутствия значимого влияния на работу сервиса. Критерии приёмки: прохождение тестов, отсутствие утечек, производительность в пределах нормы. Результат для отчёта: отчёт о тестировании, скриншоты логов до/после, графики производительности. |
| 8 | **Внедрение механизма в систему логирования** | с 05.04.2026 по 09.04.2026 | Интегрировать разработанный механизм в существующую систему журналирования сетевого взаимодействия. Настроить подключение к компонентам маршрутизации запросов и ответов. Обеспечить минимальное влияние на производительность. Провести проверку на отсутствие утечек конфиденциальной информации в среде, подобной производственной. Критерии приёмки: в access-логах всех тестовых endpoint чувствительные поля замаскированы, сервис работает стабильно без непредвиденных ошибок. Результат для отчёта: фрагмент конфигурации, примеры access-логов после внедрения. |
| 9 | **Оформление отчетных документов** | с 02.03.2026 по 05.04.2026 | Написание отчёта, оформление в соответствии с требованиями, получение отзыва от руководителей. Оформление отчётных документов в соответствии с требованиями: 1. Оформление отчёта должно быть выполнено в соответствии с методическим пособием (https://books.ifmo.ru/file/pdf/2622.pdf, разделы "Набор текста ", "Нумерация страниц и разделов ", "Заголовки разделов ", "Оформление рисунков ", "Оформление таблиц ", "Оформление формул ", "Оформление ссылок на источники ", "Оформление списка использованных источников ", "Оформление приложений"). 2. Структура документа: титульный лист, введение, основная часть, заключение, приложения. 3. В основной части подробно описывается выполнение задач этапов 2-8. |
| 10 | **Получение отзыва руководителя практики** | с 08.04.2026 по 14.04.2026 | Получить отзыв с оценкой у руководителя практики в модуле Практики. |
